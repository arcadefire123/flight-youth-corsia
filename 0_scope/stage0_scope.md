# 0단계 — 범위 확정

| 항목 | 내용 |
|---|---|
| 성격 | 리마인드용 정리 문서. 이 단계 자체의 "산출물"은 없고, 이후 모든 단계가 전제하는 결정 사항만 기록 |
| 확정 시점 | 대화 초반 (붙임2-2 검토 직후) |

---

## 1. 무엇이 문제였나

**붙임2-2(기업제안 프로그램)와 9/14 첫 멘토링 사이에 범위 차이가 있었다.**

| | 붙임2-2 기준 | 9/14 첫 멘토링(멘토) 기준 |
|---|---|---|
| 대상 문서 | 영문 국제표준 전체에서 600~1,000건 항목 자동 도출 | 한글 문서 (국내 법·시행령·시행규칙 중심) |
| 범위 | 넓게 — 문서 전반 | 좁게 — **하나의 항공사, 가상 데이터 한 셋으로 전 과정 완주** |
| 운영 인원 | 2명(광범위 영역 1인 + 핵심 영역 1인, 교차검증) | 명시 없음 — 팀은 4명으로 구성 |

붙임2-2대로 넓게 가면 "많이 뽑았지만 끝까지 안 돌아가는" 결과가 나올 위험이 있었고, 미팅 기준은 좁지만 **명령 한 줄로 최종 상쇄의무량까지 나오는 완결된 도구**를 요구했다.

## 2. 어떻게 정리했나

**미팅 기준을 우선한다.** 붙임2-2의 주차별 흐름(문서 추출 → 항목 분류 → 계산엔진 → 검증엔진 → LLM 파이프라인 → CLI)은 그대로 따르되, 각 단계의 **깊이와 판단 기준**은 멘토님이 말씀하신 좁은 범위에 맞춘다.

## 3. 최종 확정 범위

| 항목 | 확정값 |
|---|---|
| 대상 | 국내 이행의무자 **1개사** (가상 항공사) |
| 준수기간 | **1개** 이행기간 |
| 시나리오 | **1개** — 가상 데이터 한 셋을 넣으면 최종 상쇄의무량까지 끝까지 나오는 전 과정 |
| 데이터 기준 | **한글 문서** — 국제항공 탄소 배출량 관리에 관한 법률·시행령·시행규칙·고시 |
| LLM 담당 영역 | ① 절차 확인·안내 ② 서술형 항목 작성(초안) ③ 검토의견서·검증보고서의 내용 적정성 검토 |
| 절차 흐름 | 항공기운영자 계획서 → 자료 수집·제출 → 국토교통부 → 한국교통안전공단(검정) → 국토부 재검정 |
| 인원 구성 | **4명** (붙임2-2 원안은 2명이나, 담당 교수님이 "인원이 많을수록 분담에 유리하니 늘리라"고 지시) |

## 4. 용어 대응 (국제 ↔ 국내)

범위를 좁히면서 동시에 확정한 것이 국제표준 용어와 국내 법령 용어의 대응이다. 이후 모든 문서·코드에서 이 대응을 그대로 쓴다.

| 국제(Annex 16 Vol.IV) | 국내 법령 |
|---|---|
| Aeroplane operator | 항공기운영자 / 이행의무자 |
| Emissions Monitoring Plan (EMP) | 모니터링 계획 |
| Emissions Report (ER) | 배출량보고서 |
| Verification Report (VR) | 배출량검증보고서 |
| Verification body | 검증기관 |
| Offsetting Requirements (OR) | 상쇄의무량 |
| Emissions Unit Cancellation Report (EUCR) | 상쇄의무이행보고서 |
| State / Administering authority | 국토교통부장관 (사전검토·적정성검토·상쇄의무량 산정은 한국교통안전공단 위탁) |

## 5. 이 결정이 이후 단계에 미친 영향

| 단계 | 영향 |
|---|---|
| 1단계 문서 지도 | "항목 600~1,000건을 넓게 추출"이 아니라, ICAO 템플릿 6종(677건)을 **전수** 추출하고 국내 별지와 매핑하는 방향으로 진행 |
| 3단계 데이터셋 | 항공사 **1개**, 이행연도 **1개년** 기준으로 설계(처음 2027년 → 이후 SGF 공식값이 있는 2024년으로 변경). 여러 항공사·여러 연도를 다루지 않음 |
| 4~5단계 엔진 | "여러 시나리오를 일반적으로 처리"가 아니라 **한 시나리오를 끝까지 완주**시키는 것이 1차 목표. `flights_clean.csv` 하나로 최종 상쇄의무량까지 나오는지가 관문 |
| 역할 분담 | 4명 → 2트랙(문서·항목 2명 / 계산·검증 2명) 구조로 재설계. 붙임2-2의 "2인 교차검증"은 트랙 내부에서 재현 |

## 6. 팀 인원에 대한 참고사항 (사용자 제공)

붙임2-2 원안은 2인 운영 기준이지만, 담당 교수님이 "인원이 많을수록 작업을 더 분담할 수 있어 유리하다"며 4명까지 채우라고 지시하여 4인 팀으로 확정됨. 문서상 근거(붙임2-2)와 실제 운영 인원이 다른 이유가 여기 있다.

## 7. 범위 조정 — 2차 멘토링 (2026-10-06)

5단계까지 진행한 뒤 교수님·멘토님과 범위를 다시 조정했다.

| 항목 | 처음 범위 | 조정된 범위 |
|---|---|---|
| 웹 화면 | 없음 (붙임 2-2: 라이브러리·명령행 도구로만 인도) | **필수.** 종합점수 등 결과를 보여주는 화면, 직관적·두괄식 |
| 정답 데이터 | 팀이 정답셋 50건 작성 | 팀은 **견본 5건 + 판정 기준**, 골든셋 본편은 **전문가**(공항공사 박사)가 작성 |
| 정성 검증 | AI 판정 방식은 7단계에서 설계 | AI에 넣기 전 **항목별 판단 기준표**를 먼저 정함 |
| 규칙 기반 검증 | 형식·임계값·일관성 규칙을 코드로 | 그대로 유지. 근거를 기록하는 **종합점수**를 보조 지표로 추가 |
| 분석 틀 | 없음 | **페르소나·유저 시나리오**로 사용자와 사용 장면을 정의 |

결과물은 붙임 2-2의 4가지(① 항목 카탈로그 ② 계산엔진 ③ 검증엔진 ④ 검증 보고서)에 **⑤ 웹 화면**이 더해진다.
