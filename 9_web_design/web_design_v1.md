## 1. 페르소나와 유저 시나리오

> **인물 이름과 부서명은 설명을 위해 지어낸 가상의 예시다.** 실존 인물·조직과 무관하다. 소속 기관의 업무 범위만 실제 제도를 따랐다.
> 검토 대상 항공사 「한빛항공」도 3단계에서 만든 가상 항공사다.

### 1.1 P1 (주) — 공단 검토 담당자 「정유진 과장」

| 항목 | 내용 |
|---|---|
| 소속 | 한국교통안전공단 항공환경처 (가상 인물) |
| 하는 일 | 국토교통부 위탁을 받아 이행의무자가 낸 배출량보고서를 검토하고 상쇄의무량을 산정·통보 |
| 상황 | 4월 30일 제출 직후 한두 달에 업무가 몰린다. 한 사람이 여러 항공사를 맡는다 |

| 쓰는 빈도 | 항공사당 접수 직후 1회 + 보완 후 재검토 1~2회 |

**유저 시나리오** — 한빛항공의 2024년 배출량보고서와 비행 기록을 올린다. 몇 초 만에 「불만족 · 종합점수 25.8 · 위반 41건(치명 22)」이 맨 위에 뜬다. 치명 위반부터 순서대로 훑으면서 각 줄에 붙은 근거 조항을 확인하고, X-12를 펼쳐 보고값 2,051,986 t과 재계산값 1,807,081 t의 차이 244,905 t이 중요성 임계 36,142 t을 넘었음을 본다. 결과를 내려받아 보완 요청 공문에 붙인다.

### 1.2 P2 (보조) — 항공사 탄소 담당자 「박성호 대리」

| 항목 | 내용 |
|---|---|
| 소속 | 중형 항공사 안전환경실 탄소관리파트 (가상 인물) |
| 하는 일 | 연료 데이터로 보고서를 만들어 제출하고, 상쇄의무량만큼 배출권을 사서 말소 |
| 상황 | 전담이 한두 명이고 CORSIA만 보지도 않는다 |

| 쓰는 빈도 | 제출 전 자체 점검. 데이터를 고쳐가며 반복 실행 |

**유저 시나리오** — 사내 데이터를 올려 「265,773 t」을 확인하고 배출권 구매 품의를 올린다. 위반 목록에서 EMP 방법 불일치를 발견해 제출 전에 고치고 다시 돌린다. 「만족」을 확인한 뒤 제출한다.

### 1.3 P3 (언급) — 검증기관 심사원

제3자 검증기관 소속 심사원. 시행령 제8조에 따라 항공사 보고값을 그대로 믿지 않고 직접 재계산해 비교해야 하며, 그 차이가 중요성 기준 안인지로 검증의견이 갈린다. 실사 전 데스크 리뷰에서 "어디를 집중해서 볼지" 추리는 용도로 쓴다.

**별도 화면을 만들지 않는다.** 이 사람이 필요로 하는 「재계산값 ↔ 보고값 차이 ↔ 중요성 임계」는 위반 목록의 X-12 상세에 이미 전부 들어가고, 노선별 분해는 「원본 데이터」 영역에 있다.

### 1.4 설계에 주는 결론

세 사람 모두 "맨 위에 결론"을 원하지만 **그 결론이 서로 다르다.** 판정(P1) · 상쇄의무량(P2) · 재계산 차이(P3)를 한 상자에 나란히 두면 세 경우를 모두 덮을 수 있다. 화면을 역할별로 나누지 않고 하나로 유지하는 근거가 이것이다.

## 2. 종합점수 설계

### 2.1 원칙

검증의견 3종(만족 / 의견부 만족 / 불만족)은 ICAO 기준(SARPs App.6 3.10)이므로 **그대로 둔다.** 종합점수는 화면에서 상태를 한눈에 보기 위한 **보조 지표**이며, 어떤 경우에도 판정을 대체하지 않는다.

### 2.2 계산 방식 (심각도 가중 + 판정별 상한)

규칙마다 심각도에 따른 배점을 주고, 잃은 배점의 비율로 환산한다.

| 심각도 | 배점 |
|---|---|
| 치명 | 5 |
| 중요 | 2 |
| 경미 | 1 |
| 정보 | 0 |

```
계층 점수 = 100 × (1 − 해당 계층에서 잃은 배점 ÷ 해당 계층 총 배점)
원점수    = 100 × (1 − 전체 잃은 배점 ÷ 전체 총 배점)
전체 점수 = min(원점수, 판정별 상한)
```

- **SKIPPED 규칙은 분모에서 제외**한다. 판정 보류를 감점으로도 가점으로도 처리하지 않는다.
- **규칙 단위로 1회만** 계산한다. 위반 건수는 점수에 반영하지 않고 목록에 숫자로만 보여준다. (오류주입본 X-19는 1,102건이라 건수를 반영하면 한 규칙이 점수 전체를 지배한다.)
- **상한은 전체 점수에만** 적용한다. 계층별 점수는 보정 없이 원점수 그대로 표시한다.

### 2.3 판정별 상한

| 판정 | 상한 |
|---|---|
| 만족 | 100 |
| 의견부 만족 | 89 |
| 불만족 | 59 |

> **이 90·60 구간 기준은 ICAO 기준이 아니라 우리 팀이 정한 보조 기준이다.** ICAO는 점수 체계를 두지 않는다. 화면과 보고서 양쪽에 그렇게 표기한다.

상한이 실제로 적용된 경우 화면에는 **보정 전 원점수와 사유를 함께** 둔다.

```
59.0점  (원점수 97.4 · 치명 위반으로 상한 적용)
```

상한을 두는 이유: 치명 위반이 1건뿐이면 원점수가 97.4점으로 나와 판정(불만족)과 어긋나 보인다. 상한을 걸면 점수대만 봐도 판정이 읽히고(90↑ 만족 / 60~89 의견부 만족 / 59↓ 불만족), 같은 구간 안에서는 심각도에 따라 점수가 벌어진다.

### 2.4 시뮬레이션 — 6개 케이스

S-0과 S-5는 엔진 실측값이고, S-1~S-4는 중간 구간의 변별력을 보려고 만든 **가상 조합**이다.

| 케이스 | 내용 | 판정 | 원점수 | 상한 | 전체 점수 |
|---|---|---|---|---|---|
| **S-0 정상본** | 실측. 위반 0건 (SKIPPED 1: T-10) | 만족 | 100.0 | 100 | **100.0** |
| **S-1 경미 단건** | 가상. F-03 1건 | 의견부 만족 | 99.5 | 89 | **89.0** (보정) |
| **S-2 비치명 다수** | 가상. 오류주입본에서 치명을 뺀 19건 (중요 15 · 경미 4) | 의견부 만족 | 82.5 | 89 | **82.5** |
| **S-3 치명 단건** | 가상. F-04 1건 | 불만족 | 97.4 | 59 | **59.0** (보정) |
| **S-4 치명 소수** | 가상. F-04 · F-05 · F-06 | 불만족 | 92.3 | 59 | **59.0** (보정) |
| **S-5 오류주입본** | 실측. 41건 (치명 22 · 중요 15 · 경미 4) | 불만족 | 25.8 | 59 | **25.8** |

**계층별 점수 (보정 없음)**

| 계층 (규칙 수) | S-0 | S-5 |
|---|---|---|
| 형식 (18) | 100.0 | 17.8 |
| 임계값 (9, SKIPPED 1 제외) | 100.0 | 76.2 |
| 일관성 (28) | 100.0 | 12.5 |
| 정성 (8) | 100.0 | 75.0 |

### 2.5 다른 두 방식을 쓰지 않은 이유

| 방식 | 기각 사유 |
|---|---|
| **고정 감점** (치명 −15 · 중요 −5 · 경미 −1, 0 하한) | 오류주입본은 감점 합계가 409점이라 0점에 붙는다. 불만족 사례끼리 전혀 구분되지 않고, 화면에 "409점 감점"을 설명할 자리가 없다 |
| **계층별 통과율** (심각도 미반영) | 치명 1건과 경미 1건이 똑같이 98.6점이 된다. 규칙 1건당 감점이 계층 크기에 반비례해 **일관성 치명 X-19(−0.9점)이 정성 중요 Q-01(−3.1점)보다 덜 깎이는 역전**이 생긴다. 오류주입본에서 치명 T-04가 들어 있는 임계값 계층이 87.5점으로 가장 높게 나와, 가장 심각한 위반이 높은 점수 뒤에 숨는다 |

### 2.6 알아두어야 할 성질

이 방식에서 「만족」은 위반 0건을 뜻하므로 **전체 점수가 항상 정확히 100.0**이 된다. 즉 90~99 구간은 비어 있고, 종합점수는 의견부 만족·불만족 구간에서만 변별력을 갖는다. 이는 "판정이 주, 점수가 보조"라는 원칙과 일관된 결과라 그대로 둔다.

### 2.7 근거 기록 (2차 멘토링 요구사항)

점수가 나오면 반드시 함께 기록한다.

- 규칙 단위: `X-12 · 치명 · 배점 5 / 전체 194 → −2.6점`
- 계층 단위: `형식 = 100 × (1 − 37/45) = 17.8`
- 전체: `원점수 25.8 → 상한 미적용 → 25.8`

이 기록은 화면 표시용이자, 11단계 검증 보고서에 그대로 들어갈 자료다.

## 3. 화면 설계

### 3.1 레이아웃 — 요약 상자 + 단일 스크롤

```
┌──────────────────────────────────────────────────────┐
│ 한빛항공 · 2024년 배출량보고서        검토 담당자 보기 │
```

**"요약 고정"의 뜻** — 스크롤을 따라다니는 고정(sticky)이 아니라, **맨 위에 한 상자로 묶어 두는 것**이다. 전체 화면을 캡처·인쇄할 때 결론 영역이 한 덩어리로 잡히고, Streamlit에서 별도 기법 없이 안정적으로 구현된다.

### 3.2 영역별 표시 내용

| 위치 | 영역 | 표시 |
|---|---|---|
| 1 | 결과 요약 상자 | 최종 판정(ICAO 3종) · 종합점수(소수점 1자리) · 최종 상쇄의무량. 불만족이면 경고 줄. 계층별 점수 4개(보정 없음) |
| 2 | 위반 목록 | 규칙 ID · 내용 · **근거 조항(접지 않아도 각 줄에 표시)** · 건수 · 감점. 심각도 순 정렬. 줄 클릭 시 상세 펼침 |
| 3 | 정성 검증 | 「AI 참고용 · 최종 판정 아님」 배지. 7단계 연동 전까지는 자리와 현재 상태만 |
| 4 | 계산 상세 | C06~C12 중간값. 기본 접힘 |
| 5 | 원본 데이터 | 노선별 편수·CO₂·상쇄 대상 여부. 기본 접힘 |

### 3.3 표시 규칙

- **종합점수는 소수점 1자리**로 쓴다 (25.8, 100.0). 상한이 걸렸으면 `59.0 (원점수 97.4 · 치명 위반으로 상한 적용)`.
- **계층별 점수에는 상한을 적용하지 않는다.** 상자 안에 "상한 보정 없음"을 명시한다.
- **불만족일 때 최종 상쇄의무량 옆에 경고를 붙인다.** 문안: *"검증을 통과하지 못한 데이터로 계산한 값입니다. 보완 후 다시 계산해야 합니다."* 숫자를 숨기지는 않는다 — 규모 가늠에는 쓰이기 때문이다.
- **위반 1건당 근거 조항은 항상 보인다.** 펼침은 수치·예시·감점 산식을 위한 것이다.
- **정성 검증 영역은 항상 「AI 참고용」 배지를 단다.** 7단계 연동 후에도 유지한다.
- 종합점수 옆에는 「보조 지표」, 판정 옆에는 「ICAO 3종」을 작게 둔다.
- **위반 내용은 요건 문장이 아니라 위반 사실로 쓴다.** 규칙 제목은 "미해결 데이터 공백 없음"처럼 요건을 서술한 문장이라 위반 목록에 그대로 내보내면 문제가 없다는 뜻으로 읽힌다. 화면에는 "미해결 데이터 공백 있음"처럼 위반을 나타내는 문장을 쓴다. 규칙 제목(`title`)은 규칙 문서와 일치해야 하므로 바꾸지 않고, 표시용 문구를 따로 둔다(`verify/violation_text.py`). 펼친 상세에는 규칙 제목도 함께 보여 어느 규칙인지 확인할 수 있게 한다.
- **근거 조항은 엔진에 적힌 전체를 보여준다.** 둘 이상이면(예: X-01 「지침 별표7 1a · ETM 부록1 EUCR 1-a」) 앞부분만 자르지 않는다.
- **규칙 번호는 줄바꿈을 금지한다.** 「T-04」가 「T-」와 「04」로 갈리지 않도록 배지에 `white-space: nowrap`을 주고, 규칙 칸은 가장 긴 ID(X-14b)가 들어가도 남도록 78px로 고정한다. 창을 좁혀도 칸이 눌리지 않게 목록 행에 최소 폭(620px)을 두고 가로 스크롤로 넘긴다.
- **한글은 단어 중간에서 끊지 않는다.** 화면 전체(본문·사이드바)에 `word-break: keep-all !important; overflow-wrap: anywhere;`를 주고(`!important`는 Streamlit이 문단에 거는 `word-break: break-word`를 이기기 위해 필요), 「상쇄의무이행검증보고서」처럼 한 단어가 칸보다 긴 경우만 예외로 끊는다. 위반 목록은 목록 폭이 900px 이하면 근거 조항 칸을 230px 고정에서 비율(0.6fr)로 바꿔 위반 내용 칸을 넓힌다.
- **좁은 창에서는 위반 목록 한 줄을 세 줄로 쌓는다.** 목록 폭이 620px 이하가 되면 가로 스크롤 대신 1줄 규칙 번호 상자 + 감점, 2줄 위반 내용, 3줄 작은 글씨로 근거 조항 + 건수로 바꾼다. 감점(원칙 ④)이 어떤 창 폭에서도 보이게 하기 위해서다. 규칙 번호 상자는 이때도 줄바꿈 금지다.
- **표의 첫 칸(항목 이름)은 줄바꿈 금지, 표가 칸보다 넓으면 가로 스크롤로 넘긴다.** 표 칸에는 `overflow-wrap: normal`을 준다 — `anywhere`는 표 칸의 최소 폭을 글자 한 개까지 줄여 「연│료」처럼 끊는다.
- **위반 상세의 수치는 한글 이름과 천 단위 쉼표로 보인다.** 「보고값 2,051,986 t · 재계산 1,807,081 t · 차이 244,905 t」. 이름·단위·소수 자릿수는 대응표(`verify/display.py`)에 두고, 대응표에 없는 항목은 영어 이름 그대로 소수 둘째 자리까지만 보인다.
- **판정 보류가 있으면 판정 아래에 안내를 붙인다.** 판정(ICAO 3종)은 바꾸지 않는다. 빠진 자료가 서류 JSON에 들어 있는 것이면 「서류 JSON을 함께 올리면 검증됩니다」, 아니면 「필요한 자료: …」를 붙인다. 판정 보류 사유와 정성 검증의 「확인하지 못함」도 코드 이름이 아니라 한글 이름(대응표)으로 쓴다.
- **심각도는 색으로 구분하고 범례를 함께 둔다.** 치명 빨강(#D64545) · 중요 주황(#C77700) · 경미 회색(#6B7280). 색은 왼쪽 세로 띠와 규칙 배지·감점 숫자에 쓴다. **경미 위반도 상자가 보여야 한다** — 배경을 페이지 색과 같게 두면 경미 줄만 테두리가 사라지므로, 모든 줄에 옅은 회색 배경과 테두리를 준다.

### 4.1 구현 시 지킨 것

- Streamlit으로 만들고, 웹과 통합 명령(`python -m corsia full`)은 **같은 엔진**을 호출해 결과가 항상 일치해야 한다.
- 종합점수는 웹이 아니라 **검증엔진 안에서** 계산한다. 화면은 표시만 한다. (CLI에서도 같은 점수가 나와야 하고, 11단계 보고서가 이 값을 쓴다.)
- 점수 산출 근거(규칙별 감점·계층 산식·상한 적용 여부)를 결과 객체에 담아 내려받기에 포함한다.
- API 키가 없으면 정성 검증 영역은 현재 상태(서술 작성 여부)만 보여주고 나머지는 정상 동작해야 한다.
- **윈도우에서 외부 도구가 직접 읽는 텍스트 파일(`requirements.txt`, `.streamlit/config.toml` 등)에는 한글을 넣지 않는다.** 한국어 윈도우의 pip 등은 파일을 cp949로 읽어 UTF-8 한글이 있으면 `UnicodeDecodeError`로 실패한다. 설명이 필요하면 README에 쓴다. `check_all.py`가 이 파일들이 ASCII인지 점검한다.
