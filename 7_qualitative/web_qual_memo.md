- 정상 서류: **Q-01만 보완 필요**(자료 흐름이 보고서 작성 단계 없이 끝나 C2·C3 부족, 기준표의 부족 예시와 같아 판정이 맞음). 사용법 6절의 「부실한 항목만 보완 필요가 정상」은 틀린 설명이라 고침 → 정상본은 Q-01만, 서술 부실 예시는 Q-01·Q-03
- 발견한 문제와 고친 것: ① `--mock ok` 뒤에 `--weak`를 돌리면 입력이 같은 6개 항목이 모의 응답 기억에 걸려 이유가 「모의 응답입니다.」인 가짜 판정이 나옴 → 모의 실행은 기억을 안 읽고 안 쓰며 항목에 `source`를 넣어 진짜 실행에서 mock 출처를 무시(시나리오 시험 추가) ② `run_web_qual.py --help`의 `(%)` 때문에 ValueError → `%%`로 고침(시험 추가). **이전에 모의 실행이 남긴 `engine/ai_cache/` 파일은 새 코드가 알아보고 무시한다**(지워도 됨)

## 팀장 PC 인수 시험 순서

1. **백업**: `engine` 폴더를 통째로 복사해 둔다. 압축을 덮어쓴다(새 파일만 추가되고 기존 파일은 안 바뀜).
2. `python test_web_qual.py`(39개), `python check_all.py`(모두 통과)
3. 키 없이 흐름: `python run_web_qual.py --mock ok` → 8개 항목이 하나씩 나오고 상태 ok
4. **실제 호출 1회**(키 필요, 약 $0.10, 약 20초): `python run_web_qual.py --weak --out result.json`. 확인할 것: 항목별 판정·이유·근거 조항이 나오는가, 7번 호출이 4개씩 동시에 나가 약 20초 안에 끝나는가(`timing.seconds`), 비용이 $0.10 안팎인가, `result.json`에 PC 경로가 없는가
5. 같은 명령을 한 번 더: 모든 항목이 「기억」으로 나오고 비용 0
6. 키 없는 상태(환경 변수 임시 제거): `python run_web_qual.py` → 오류 없이 안내 한 줄
7. `7_qualitative/web_qual_usage.md`를 채팅 A에 그대로 전달

## 한계

- 실제 API로 이 모듈을 돌려 보지는 않았다(키 없는 환경). 호출 방식은 7단계 판정 시험에서 쓴 `client.call`과 판정 코드를 그대로 쓰고 모의 응답으로만 시험했다. 4번 단계가 첫 실제 확인이다.
- 동시 호출은 API 속도 제한을 받을 수 있다(429 → 한 번 재시도, 계속되면 `network_error`로 표시, 다시 실행하면 받은 항목은 기억에서 가져옴). 계정 등급에 따라 `max_workers`(기본 4)를 낮춰야 할 수 있다.
- 비용 추정은 입력 글자 수 × 0.95토큰 + 출력 900토큰으로 넉넉히 잡은 값이며(실측 호출 1건 약 $0.013), 실제 차감액은 Console이 기준이다.
- 이 모듈은 서술이 사실인지·다른 서류와 값이 맞는지는 판정하지 않는다(기준표 공통 규칙).
