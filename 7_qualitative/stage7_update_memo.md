### 확인한 사실 (7단계 설계에 영향)

| 내용 | 근거 | 설계에 주는 영향 |
|---|---|---|
| 모델 ID: `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5` | Claude Platform Docs 모델 페이지 | `models.py`에만 적음 |
| 단가(USD/100만 토큰, 입력/출력): Haiku 0.10/0.50, Sonnet 2/10, Opus 4/20. 배치는 입력·출력 50% 할인 | Haiku는 공식 모델 페이지, Sonnet·Opus는 공식 가격표를 인용한 보도 여러 건 (2026-11-01 확인) | 예상 비용 표시. 실제 차감액은 Console 비용 페이지가 기준 |
| Haiku 5.5는 프롬프트가 10만 토큰을 넘으면 요청 전체 단가가 5배 | 공식 모델 페이지 | 원문을 통째로 넣지 않는 RAG 설계와 맞음. 비용 표시에 반영 |
| Haiku 5.5는 기본값이 아닌 temperature·top_p·top_k와 assistant 미리 채우기(prefill)를 400 오류로 거절 | 공식 Haiku 5.5 이전 안내서 | **판정 일관성을 temperature 0으로 잡을 수 없다.** 기준표·출력 형식 고정과 같은 입력 반복 측정으로 확보한다. Sonnet·Opus 5.5도 같은지는 E 단계에서 확인 |
| 5.5 모델은 응답에 생각 블록이 먼저 올 수 있음 | 공식 이전 안내서 | 응답에서 type이 text인 블록만 읽음 |
| 아나콘다 기본 brotli(1.0.9)에서는 응답 압축 해제 중 TypeError가 나고, SDK는 이것을 「연결 실패」로 보고함 | 팀장 PC 실측 (2026-11-01) | 호출부가 **압축 없는 응답을 요청**(`Accept-Encoding: identity`)하도록 수정. 연결 실패 안내에 「응답을 푸는 단계의 오류일 수 있음, `pip install -U brotli`」를 추가하고, 원인이 압축 해제 쪽이면 그렇게 따로 표시 |
| Haiku 5.5는 생각(adaptive thinking)이 기본으로 켜져 있고, 생각 토큰도 max_tokens 안에 들어가며 출력 단가로 청구됨. max_tokens가 작으면 생각만 하다 답(text) 없이 끝날 수 있음 | 공식 「What's new in Haiku 5.5」, 「Prompting Claude Haiku 5.5」 | 판정용 max_tokens 기본 상한 4000(`MAX_TOKENS_JUDGE`). 상한은 청구액이 아니라 상한일 뿐(실제로 만든 토큰만 청구). 답이 상한에서 끊기면 `truncated`로 표시 |
| 생각은 `thinking: {"type": "disabled"}`로 끌 수 있으나 effort가 high 이하일 때만. 공식 권장은 끄기보다 effort(low·medium·high·xhigh·max, Haiku 기본 medium)로 조절 | 위 공식 문서 | 호출부에 `thinking`·`effort` 선택 추가. SDK 버전과 상관없이 동작하도록 요청 본문으로 보냄 |
| 생각을 끄거나 low effort면 Haiku 5.5가 **추론 같은 문장을 답에 섞는** 경우가 있음(공식 안내는 그때 adaptive·medium으로 바꾸라고 함) | 「Prompting Claude Haiku 5.5」 | JSON 출력이 깨질 수 있는 지점. E 단계에서 설정별로 JSON 해석 실패율을 잼 |
| 연결 시험(설정 없음, 짧은 질문)은 출력 4토큰 | 팀장 PC 실측 | 간단한 질문에는 adaptive 생각이 거의 쓰이지 않음. 판정처럼 긴 입력에서는 다를 수 있어 E에서 잼 |

### 호출부 수정 (B와 함께 전달, 2026-11-01)

`engine/corsia/ai/client.py`, `engine/corsia/ai/__init__.py`, `engine/ai_smoke_test.py` 3개 파일. 모두 A에서 새로 만든 파일이라 기존 엔진 파일은 여전히 수정 없음.

| 바뀐 것 | 내용 |
|---|---|
| 압축 없는 응답 요청 | 모든 호출에 `Accept-Encoding: identity`. 오래된 brotli가 있는 다른 PC에서도 같은 문제가 나지 않게 함 |
| 연결 실패 안내 | 오류의 원인 사슬과 오류 위치를 보고 압축 해제 쪽이면 「응답을 푸는 단계의 오류」로 따로 표시. 일반 연결 실패 안내에도 이 가능성과 `pip install -U brotli`를 적음 |
| 생각·노력 수준 선택 | `call(..., thinking=..., effort=...)`. thinking은 adaptive 또는 disabled, effort는 low·medium·high·xhigh·max. 생각 끄기는 effort high 이하에서만 허용(그 외는 호출 전에 막음) |
| 답 잘림 표시 | `CallResult.truncated`(stop_reason이 max_tokens). 비용 줄에 「[주의] max_tokens에 닿아 답이 잘렸을 수 있음」 |
| 판정용 상한 | `MAX_TOKENS_JUDGE = 4000` |

이 채팅에서 한 점검: 요청 헤더에 `Accept-Encoding: identity`가 실제로 들어감, thinking·effort가 요청 본문에 들어가고 지정하지 않으면 빠짐, 샘플링 값 없음, 잘못된 설정 조합 거절, 압축 해제 오류(맨 TypeError 포함)와 일반 연결 실패 구분, 가짜 키 실제 호출 401·디버그 로그 켠 상태 키 흔적 0건, `check_all.py` 10항목 통과.

### 설정 시험과 Sonnet 5.5의 「생각 끄기」 (2026-11-13, 팀장 PC)

| 설정 시험 | 결과 |
|---|---|
| smoke-low (adaptive·low, Q03-S1) | 통과. 정답 충분 / AI 충분. 입력 2,333 · 출력 790 · $0.0126 · 14초. 같은 사례의 파일럿 기본 설정(출력 894 · $0.0136) 대비 출력 12% 적음(1회씩이라 참고) |
| smoke-nothink (`--thinking disabled`) | HTTP 400 요청 형식 오류, 호출 0 · 비용 $0 |

**원인 (공식 문서 확인)**: 「Claude Sonnet 5.5 migration guide」(platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)에 따르면 Sonnet 5.5는 `thinking: {"type": "disabled"}`를 400 오류로 거절한다. 생각을 끄는 올바른 요청은 **`thinking: {"type": "between_tools"}`**(가장 낮은 생각 설정, 도구가 없으면 응답에 text만 옴). 조건: 노력 수준 low·medium·high에서만(xhigh·max는 400), 다른 필드(display·budget_tokens 등)와 같이 못 보냄. 대화 중간에 노력 수준을 바꾸면 400인데 우리는 호출마다 새 대화라 해당 없음.

**공식 문서에서 함께 확인한 것**
- `thinking`을 안 보내면 adaptive 생각이 켜짐. API 기본 노력 수준은 **high**. → 파일럿과 E3-1의 「기본 설정」은 **adaptive 생각 + 노력 high**
- 노력 수준은 low·medium·high·xhigh·max 다섯 단계이고 Sonnet 5와 다시 보정되어 같은 이름이라도 같은 양이 아님. 문서는 「노력 수준을 두세 단계로 다시 돌려 보라」고 안내. 지연이 중요한 일은 medium이나 low에서 시작해도 된다고 함
- 생각 토큰도 max_tokens에 들어가고 출력 단가로 청구됨(이미 반영: 판정용 max_tokens 4,000, 파일럿 최대 출력 2,016에서 잘림 0)

**결정 ((가) 올바른 방식으로 한다, (나)·(다) 아님)**: E3-3은 `between_tools` + 노력 **high**로 한다. E3-1(adaptive·high)과 노력 수준이 같아서 「생각 끄기」의 효과만 따로 볼 수 있고, E3-2(adaptive·low)와 합치면 생각과 노력 수준의 효과를 나눠 볼 수 있다.

| 구성 | 생각 | 노력 | 보는 것 |
|---|---|---|---|
| E3-1 기본 (3회 반복) | adaptive(기본) | high(기본) | 기준선, 반복 일치율 |
| E3-2 | adaptive | **low** | 노력을 낮춰도 정확도가 유지되는지 |
| E3-3 | **between_tools**(`--thinking off`) | high | 생각을 꺼도 정확도가 유지되는지 |
| E3-2b (선택) | adaptive | medium | E3-2가 기본보다 떨어질 때 어디서 떨어지는지 |

**E3-2를 낮은 노력으로 해도 되는가**: 된다. 설정 시험 통과, 공식 문서가 노력 수준을 두세 단계로 시험하라고 안내. 다만 비용 차이는 작다(출력 12% 감소는 약 $0.001/회). 정확도가 기본과 같거나 거의 같을 때만 의미가 있으므로, E3-2가 기본보다 눈에 띄게 낮으면 E3-2b(medium, ≤ $2.0)를 더해 단계를 찾는다. 같으면 E3-2b는 생략한다.
