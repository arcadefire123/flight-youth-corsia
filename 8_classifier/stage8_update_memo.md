## 1. 무엇을 만들었나

AI가 카탈로그 667개 항목의 속성 7가지(주체·단계·의무성·시점·기한·입력유형·근거·연결필드)를 채운다. **코드가 정할 수 있는 것은 코드가, 글을 읽어야 하는 것만 AI가** 한다(「계산과 명확한 규칙은 코드, 글을 읽고 판단하는 일만 AI」 원칙).

| 속성 | 정하는 법(판정 기준) | 혼합에서 누가 | 근거 자료 |
|---|---|---|---|
| 주체 | 템플릿으로 정함(기준 6) | 코드 | `template_rules_v1.json` |
| 단계 | 템플릿으로 정함(기준 4) | 코드 | 〃 |
| 시점·기한 | 서류의 제출 기한(기준 2). VR만 두 기한 중 고름 | 코드 (VR은 AI) | 〃 |
| 입력유형 | ICAO 칸의 실제 모양(기준 3) | 선택·자동계산은 코드, 나머지(수치·텍스트·서술·첨부)는 AI | `template_cells_v1.json`(원본 엑셀에서 읽음) |
| 의무성 | 칸·상위 항목의 조건 표현(기준 5) | AI (코드가 단서와 상위 항목을 찾아 줌) | 항목 글, 국내 작성방법, 상위 항목 |
| 근거 | 국내 서식 → 별표 → 지침 조문 → 법령(기준 8) | 국내 서식이 있는 칸은 코드가 조립, VR은 AI | 국내 별지 매핑, ICAO 절 색인 |
| 연결필드 | 다른 템플릿의 같은 값 칸(기준 7) | AI (코드가 후보 최대 8개를 찾아 줌) | 카탈로그 안의 글자 조각 유사도 + ICAO 원본 칸 글 |

**법령 문서를 검색해서 붙이는 RAG는 쓰지 않는다**(분석 결과 불필요). 대신 판정 기준과 템플릿 상수표를 담은 「참고 카드」(약 2,700 토큰)를 모든 호출에 넣는다. `python classify_items.py --print-card` 로 카드를 볼 수 있다.

변형 3가지:
- **rule**: 코드만(비용 0). 규칙만으로 어디까지 되는지의 기준선
- **ai**: AI만. 코드가 정한 값을 주지 않음(카드·견본 5건·항목 맥락·연결 후보만)
- **hybrid**: 코드의 확정값은 그대로 두고 나머지만 AI가 채움. AI가 코드 값에 이의가 있으면 값은 바꾸지 않고 「이의」로 표시(규칙이 안 맞는 곳을 찾는 용도)

## 3-3. 표본 30건 분석과 규칙 v2 (2026-11-15)

팀장이 표본 30건(`sample30`, 실제 비용 $0.115)을 사전 점검해 올린 결과를 분석해 규칙을 보정했다. **분석 근거와 AI 이의 8건의 원인**은 채팅 답변에 있고, 코드 쪽 변경은 아래와 같다.

**① 추출기 버그 수정(가장 중요): OoM 점검표의 선택 목록을 못 읽고 있었다.** OoM 서식 「Identification」 시트의 Status 열(F8:F12, F14:F21, … 9개 범위)에는 다른 시트(`Drop down list`!A2:A6)를 가리키는 **확장(x14) 데이터 검증**이 있어 목록이 OK / Yes / No / Not Applicable이다. openpyxl은 확장 검증을 읽지 못하고, 카탈로그 「3_드롭다운_원본」 시트에도 이 목록이 빠져 있어 추출기 v1이 놓쳤다. 골든셋 OoM 6건을 작성자 4명이 모두 「선택」이라고 쓴 것이 맞았다. v2 추출기는 원본 XML에서 일반·확장 데이터 검증을 모두 읽는다. 결과: 선택 목록 항목 58 → 123개(OoM 64개, VR 1개). 골든셋 1차 OoM 6건(F0471·F0474·F0475·F0476·F0477·F0536)은 모두 코드가 「선택」으로 확정한다. **카탈로그 보정 요청(카탈로그 담당 채팅에 전달)**: 「3_드롭다운_원본」 시트에 누락된 목록 2개 — ① 1.4 OoM / Identification / F8:F12 F14:F21 F25:F30 F32:F35 F38:F49 F54:F55 F58:F65 F67:F71 F74:F117 / OK, Yes, No, Not Applicable ② 1.6 VR / Scope of Verification Report / C11:K12 / 「Verification of aeroplane operator’s Emissions Report without CORSIA eligible fuels, …」(검증 범위 선택 목록). 이로써 사전 점검에서 F0589(VR 검증 범위)를 「서술 타당」으로 본 것은 틀렸고 서식에는 선택 목록이 있다(규칙 v2는 선택으로 정함).

**② 입력유형 규칙 v2** (판정 기준 3의 「칸의 실제 모양」을 더 충실히): 선택 목록 → 수식 → 첨부 표현 → **날짜 서식(설정값)** → 숫자 검증·서식 → **큰 칸(너비 3 이상·면적 12 이상)** → 서술 단서(세부라벨, 없으면 항목명) → 수치 단서 낱말(질문 문장·텍스트 서식 `@`는 제외) → 텍스트. 표본의 규칙 오류 5건(F0006·F0126·F0142·F0523·F0579)과 AI가 규칙의 틀린 힌트를 따라간 F0084가 해소된다. 견본 5건의 입력유형은 모두 그대로 맞는다. 이 보정은 칸 구조에 근거한 것이며 AI 답에 맞춘 것이 아니다. 진짜 시험은 골든셋이다.

**③ 근거**: 국내 항목번호가 섹션 번호뿐인 29개 항목(EUCR 표 열 등)은 규칙이 「지침 별지 제4호서식 3 / 지침 별표 7 3 / …」로 조립한다(형식은 팀 확인). 검증기: 「ETM 부록1 1.6 VR -」처럼 항목번호 자리가 비정상이면 형식 오류로 표시.

**④ AI 지시문**: 「이유」를 「값」보다 먼저 쓰게 하고 「이유가 강행이면 값도 강행」을 명시(F0160의 이유·값 불일치 대응). 효과는 표본 재실행으로 확인한다.

**⑤ 합의 안건 연동 설정(코드 변경 없이 규칙표만 고치면 되도록)**: `template_rules_v1.json`에 `입력유형_설정`(날짜 서식 칸 값, 기본 「텍스트」 = 안건 11 제안)과 `소제목_줄`(정책 none/exclude/blank_input, ids 목록 = 안건 12). 결정 후 값만 바꾸고 `--refresh-rules`를 돌리면 된다(비용 0). `exclude` 정책의 소제목 줄은 AI를 부르지 않는다. OoM 안건 13(의무성·연결 의미)과 안건 4는 합의 후 같은 방식으로 규칙표·카드에 반영한다.

**⑥ 소제목 후보 목록**: `8_classifier/heading_candidates_v1.xlsx`(24개: EMP 2, ER 4, CEF 8, OoM 8, VR 2, 「하위 항목 있음」·「다음 항목」 열과 「소제목/일반 항목/판단 불가」 드롭다운). 입력이 다음 줄에 있는 일반 항목(`Reporting year*`, `Did any data gaps…`, VR s1·s2 등)도 섞여 있어 코드로 자동 판정하지 않고 팀이 표시한다. 합의 뒤에 확정 ID를 `소제목_줄.ids`에 넣는다. 합의 회의에서 쓰면 된다.

**표본 결과에 새 규칙을 적용한 미리보기(AI 호출 없이 `--refresh-rules`)**: 코드 몫 5칸이 바뀐다 — F0497·F0510·F0523·F0552(OoM) 입력유형 텍스트 → 선택, F0589(VR) 서술 → 선택. AI가 채운 값(F0084·F0006 등)은 AI를 다시 불러야 바뀐다.

## 4. 골든셋 채점 규칙

- 골든셋 파일: `6_goldenset/expert_request/골든셋_작성양식_v1.xlsx`와 같은 모양, 「1_작성할항목」 L~R열에 팀원이 채움. 파일이 여러 개여도 폴더째 주면 ID로 합친다. 같은 ID를 다르게 쓴 파일은 보고서에 「충돌」로 표시
- **예시용과 채점용을 섞지 않는다**: 프롬프트의 예시는 확정 견본 5건뿐이고 골든셋 항목은 프롬프트에 들어가지 않는다. 골든셋 일부를 예시로 쓰기로 정하면 `--exclude`로 채점에서 뺀다
- 속성마다 따로 채점한다(평균 하나로 말하지 않음). 근거는 조항을 `/`로 나눈 **집합**이 같으면 정답(순서 무관), 부분 일치(Jaccard)도 같이 보고. 연결필드는 집합 비교(「-」는 빈 집합). 시점·기한은 「4월 30일」→「4/30」만 정규화
- 정답이 **「기준 없음: 이유」**인 칸은 headline에 섞지 않고 따로 센다(분류기가 「기준 없음」을 냈는지 일치만 봄)
- 보고서에 채점 기준 문구가 들어간다: 기본 「팀 골든셋(전문가 검토 전)」. 박사님 검토를 반영한 뒤에는 `--golden-label "팀 골든셋(전문가 검토 후)"`
- 틀린 칸은 `오답원인분석표.xlsx`에 모인다(원인 드롭다운: 원문이 애매 / 기준이 모호 / 조항을 잘못 찾음 / 정답이 틀림 / 코드 규칙의 한계 / AI가 기준을 안 따름 / 기준 없음 / 기타) → 8단계 순서 6을 팀원이 채움

## 5. 보고에서 꼭 설명할 것 (정직한 해석)

1. **규칙만** 정확도는 AI 능력의 증거가 아니다. 판정 기준이 정한 규칙의 정확도다. 그래서 세 갈래로 나눠 보고한다
2. 규칙은 확정 견본 5건을 보며 다듬었다(견본은 채점에서 빠져 있음). 골든셋 채점이 규칙의 첫 독립 시험이다. 견본 5건에서 규칙은 코드 몫 속성 전부를 맞히고 연결필드 2건·VR 근거 1건만 못 맞힌다(예상된 한계)
3. **AI만**의 근거는 불리하다: 국내 서식의 섹션 번호(예: 5.b4))는 코드가 별지 매핑을 조회해 넣는 값이라 AI만 변형에는 주지 않는다. 이 차이는 추론 능력이 아니라 조회의 차이다
4. 연결필드 후보 검색은 견본 2건에서만 확인했다(후보 8개 안에 정답 포함 2/2). 골든셋에서 후보 재현율(정답이 후보 안에 있었는지)을 따로 보면 연결필드 오답이 「후보가 없어서」인지 「AI가 못 골라서」인지 가를 수 있다
5. PPT(11/19) 문구 제안: 「팀 골든셋 기준, 전문가 검토 진행 중. 속성별 정확도는 규칙만 / AI만 / 혼합으로 구분해 보고」
